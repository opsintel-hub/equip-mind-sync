# แยกเมนู "ส่งคืนของเสีย" + Flow จำหน่าย/ทำลาย 2 ชั้นอนุมัติ

## 1. ตอนนี้ระบบทำงานอย่างไร (ของจริงในระบบตอนนี้)

เมนู รับเข้า > "นำของเสียเข้าระบบ" (`/defective-return`) และ "อนุมัติจัดการของเสีย" (`/disposal-approval`) ใช้ตาราง `defective_returns` ร่วมกัน

```text
ผู้แจ้ง/ช่าง/หน้างาน สร้างใบของเสีย  (status = pending_warehouse_entry)
        ↓  คลังกด "ยืนยันรับเข้า"  (ตัด stock เข้า WH-DEFECT ทันที)
   dispose_status = pending_disposal_review        ← แท็บ "รออนุมัติ"
        ↓  ผู้อนุมัติเลือกวิธี: ทำลาย / ขายซาก / CSR / ซ่อมคืนคลัง
   dispose_status = approved                        ← แท็บ "อนุมัติแล้ว"
        ↓  กด "เสร็จสิ้น" + แนบรูปหลักฐาน (บังคับกรณีทำลาย/ขายซาก/CSR)
   dispose_status = completed + ลง stock_movements  ← แท็บ "เสร็จสิ้น"
```

ข้อจำกัดที่พบตอนนี้:
- **อนุมัติชั้นเดียว** — คนกดอนุมัติวิธีจัดการ = คนเดียวจบ (ฟิลด์มีแค่ `disposal_approved_by/at`)
- สิทธิ์เข้าหน้านี้ผูกกับ `manager_approval` (ปนกับอนุมัติเบิกทรัพย์สิน) — **บัญชียังไม่มีสิทธิ์เห็น**
- ที่มาของของเสียรองรับ `billboard / from_issue / from_assessment / warehouse` แต่**ไม่มีสายงาน "ของหมดอายุในคลัง"** โดยเฉพาะ (เช่น สี ทินเนอร์)
- ไม่มีรายงานสรุปการจำหน่าย/ทำลายแยกเมนู

## 2. Flow ที่แนะนำ (2 กรณี)

หลักการสำคัญเรื่อง "ตัดสต็อก": ตัดสต็อกหลัก (`quantity_in_stock`) เฉพาะกรณีที่ของ **ยังอยู่ในคลัง** เท่านั้น
ของที่ถอดจากป้าย/เบิกออกไปแล้ว สต็อกหลักเป็น 0 อยู่แล้ว → ไม่ตัดซ้ำ ให้ "รับเข้าคลังของเสีย" เท่านั้น

### กรณี A — ของถอดจากป้าย / ชำรุดจากหน้างาน (ของไม่ได้อยู่ในคลัง)
```text
ช่างถอดจากป้าย → ใบของเสีย → คลังยืนยันรับเข้า
   ⮞  ไม่ตัด quantity_in_stock (เพราะตอนเบิกติดตั้งตัดไปแล้ว)
   ⮞  รับเข้าคลังของเสีย (WH-DEFECT) + ลง stock_movement แบบ "รับเข้าของเสีย" (movement +qty เข้า WH-DEFECT)
   → เสนอวิธีจัดการ → อนุมัติชั้น 1 → อนุมัติชั้น 2 → บัญชีรับทราบมูลค่า
   → ดำเนินการจริง + แนบรูป → เสร็จสิ้น + ลง stock_movements (จำหน่ายออก)
```
⚠️ ปัจจุบัน `deductStockToQuarantine()` ลบ `quantity_in_stock` ทุกกรณี (floor 0) ทำให้ Case A ถูกตัดซ้ำจากฐาน 0 และลง movement ยอดติดลบจาก 0 → ต้องแก้ให้ตรวจ `source_type` ก่อนตัด:
- `billboard / from_issue / from_assessment` → ไม่ตัดสต็อกหลัก, ลง movement "receive เข้า WH-DEFECT"
- `warehouse` → ตัดสต็อกหลักตามเดิม

### กรณี B — ของในคลังหมดอายุ / เสื่อมสภาพ (ของยังอยู่ในคลัง)
**หมดอายุ ≠ ใช้ไม่ได้เสมอไป** ดังนั้น:
- ของหมดอายุแต่ **ยังใช้งานได้** → เบิกได้ปกติ ระบบแค่ "แจ้งเตือนให้ตรวจสอบ" (ไม่บังคับตัดจำหน่าย)
- ของหมดอายุและ **ยืนยันว่าใช้ไม่ได้แล้ว** → เข้าสายตัดจำหน่าย (เจ้าหน้าที่คลัง/เจ้าของของเปิดใบ)

```text
คลังตรวจพบหมดอายุ (ระบบเตือนจาก expiry_date) → ตรวจสอบสภาพจริง
   หากยังใช้ได้ → ทำเครื่องหมาย "ยังใช้ได้" ให้เบิกปกติได้ต่อ
   หากใช้ไม่ได้ → เปิดใบตัดจำหน่าย ระบุจำนวน + เหตุผล + รูปสภาพจริง (source_type = 'expired', is_expired=true)
   → คลังยืนยัน "ตรวจนับแล้ว" → ตัด quantity_in_stock ออก + ย้ายเข้า WH-DEFECT
   → อนุมัติชั้น 1 → อนุมัติชั้น 2 → บัญชีรับทราบ
   → ทำลาย/ขายซาก + แนบรูป → เสร็จสิ้น
```
ทั้งสองกรณีมาบรรจบที่ **หน้าอนุมัติเดียวกัน** ต่างกันแค่ป้าย "ที่มา" และทิศทางการตัดสต็อก — ไม่ต้องสร้าง 2 ระบบ

## 3. การอนุมัติ 2 ชั้น + สิทธิ์

| ชั้น | ใคร | สิทธิ์ (function key ใหม่) | ทำอะไร |
|---|---|---|---|
| เสนอ | คลัง / ช่าง / เจ้าของของ | `disposal_request` | เปิดใบ + เสนอวิธีจัดการ |
| ชั้น 1 | หัวหน้าฝ่ายเจ้าของของ | `disposal_approve_l1` | ยืนยันว่าเสียจริง/เห็นชอบวิธี |
| ชั้น 2 | ผู้จัดการทรัพย์สิน / ผู้บริหารคลัง | `disposal_approve_l2` | อนุมัติขั้นสุดท้าย |
| บัญชี | ฝ่ายบัญชี | `disposal_finance` | เห็นทุกใบ + มูลค่า + ยืนยันรับทราบ (ไม่บล็อกงาน) |
| รายงาน | ผู้บริหาร/ตรวจสอบ | `disposal_report` | ดูรายงานอย่างเดียว |

กติกาสำคัญ:
- **คนเดียวกันกดชั้น 1 และชั้น 2 ไม่ได้** (ระบบบล็อกด้วย user id)
- ชั้น 2 กดได้เฉพาะใบที่ผ่านชั้น 1 แล้ว
- ปฏิเสธได้ทุกชั้น พร้อมเหตุผลบังคับ → ใบกลับไปให้ผู้เสนอแก้
- ยังคง scope ตามฝ่าย/แผนกเดิม (บัญชีเห็นข้ามฝ่ายได้)

## 4. โครงเมนูใหม่

ย้ายออกจากกลุ่ม "รับเข้า" → กลุ่มใหม่ **"ส่งคืนของเสีย"**
- นำของเสียเข้าระบบ (`/defective-return`)
- ตัดจำหน่ายของหมดอายุ (`/defective-return?mode=expired`) — สายใหม่กรณี B
- อนุมัติจัดการของเสีย (`/disposal-approval`) — เพิ่มแท็บ รอชั้น 1 / รอชั้น 2 / รอบัญชี / อนุมัติแล้ว / เสร็จสิ้น / ปฏิเสธ
- รายงานของเสียและการจำหน่าย (`/disposal-report`) — เมนูใหม่

## 5. รายงานที่จะสร้าง (`/disposal-report`)

- Summary card: จำนวนใบ / จำนวนชิ้น / **มูลค่ารวมที่ตัดจำหน่าย** แยกตามวิธีจัดการ
- ตาราง 1 บรรทัด = 1 ใบ: เลขที่, วันที่, รหัส/ชื่อ, S/N, ฝ่าย/แผนก, ที่มา (ป้าย/เบิก/ประเมิน/หมดอายุ), จำนวน, ราคาต่อหน่วย, มูลค่ารวม, วิธีจัดการ, ผู้อนุมัติชั้น 1, ผู้อนุมัติชั้น 2, บัญชีรับทราบ, สถานะ, วันที่ดำเนินการ, หลักฐาน
- ตัวกรอง: ช่วงวันที่, ฝ่าย (DepartmentMultiFilter), วิธีจัดการ, ที่มา, สถานะ
- Export Excel ด้วยคำไทยตรงกับ UI + ค้นหา 2 ช่อง (S/N และ ทั่วไป) ตามมาตรฐานระบบ

## 6. ต้องอัปเดตอะไรที่ "จัดการผู้ใช้"

- เพิ่ม 5 function keys ใหม่ใน `SYSTEM_FUNCTIONS` + คำอธิบายใน `FunctionDescriptions.tsx`
- `PermissionWizard.tsx` / `PermissionMatrix.tsx`: แสดงกลุ่มใหม่ "ส่งคืนของเสีย"
- `permission_templates`: เพิ่ม preset **"ฝ่ายบัญชี"** (`disposal_finance` + `reports`) และเติมสิทธิ์ใหม่ให้ preset เจ้าหน้าที่คลัง (`disposal_request`) และ Manager (`disposal_approve_l1`)
- **Migration ข้อมูลเดิม:** ผู้ใช้ที่มี `manager_approval` อยู่แล้ว ให้ได้ `disposal_approve_l1` อัตโนมัติ เพื่อไม่ให้ใครหลุดสิทธิ์ตอนเปลี่ยน
- ใบเก่าที่ `dispose_status = approved/completed` แปลงเป็นสถานะใหม่ให้ตรงกัน (ถือว่าผ่านครบทุกชั้นแล้ว)

## รายละเอียดเชิงเทคนิค

- Migration `defective_returns` เพิ่มคอลัมน์ (nullable ทั้งหมด ข้อมูลเก่าไม่พัง):
  `l1_approved_by/at/notes`, `l2_approved_by/at/notes`, `finance_ack_by/at/notes`,
  `proposed_method`, `proposed_by/at`, `disposal_rejected_by/at/reason`,
  `unit_price_snapshot numeric`, `total_value numeric`, `expiry_date date`
- `dispose_status` ค่าใหม่: `pending_l1` → `pending_l2` → `approved` → `completed`; `rejected_l1` / `rejected_l2`
  (backfill: `pending_disposal_review` → `pending_l1`)
- Trigger/DB function ตรวจว่า `l2_approved_by <> l1_approved_by` และห้ามข้ามชั้น
- RLS: อ่านตาม scope ฝ่าย/แผนกเดิม + เพิ่มเงื่อนไข `has_function_permission(auth.uid(),'disposal_finance')` ให้บัญชีอ่านข้ามฝ่ายได้; เขียนได้เฉพาะผู้มีสิทธิ์ชั้นนั้นๆ
- ไฟล์ที่แก้: `AppSidebar.tsx` (กลุ่มเมนูใหม่), `App.tsx` (route `/disposal-report`), `DisposalApproval.tsx` (แท็บ + 2 ชั้น + การ์ดมูลค่า), `DefectiveReturnEntry.tsx` (โหมด `expired` + ดึงของใกล้/เลยหมดอายุมาเลือก), `useFunctionPermissions.tsx`, `FunctionDescriptions.tsx`, `PermissionWizard.tsx`
- ไฟล์ใหม่: `src/pages/DisposalReport.tsx`
- ไม่แตะ flow Swap / Assessment / Claim และไม่เปลี่ยนกลไกตัด stock เข้า WH-DEFECT เดิม
