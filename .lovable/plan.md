# รับคืนแบบแยก "ของดี / ของเสีย" + เชื่อมเข้าคลังและ Swap

## เคสตัวอย่างที่ต้องรองรับ
เบิก 10 ชิ้น (ติดตั้งป้าย + ต้องคืน) ออก Route ซ่อม
- ใช้จริง 4 ชิ้น → ระบุป้าย 4
- ไม่ได้ใช้ 6 ชิ้น → คืนของดีเข้าคลัง
- ถอดของเสียกลับมา 4 ชิ้น → เข้าสายของเสีย

## 1. รับคืนต่อบรรทัด (แทนการคืนรวมทั้งใบ)
ปุ่ม "รับคืน" ย้ายมาอยู่ระดับบรรทัดสินค้า เปิด Dialog เดียวกรอกได้ 3 ก้อน:
- **คืนของดี (ชิ้น)** + ฝ่าย / คลัง / ตำแหน่งจัดเก็บ → บวกเข้าสต็อกทันที (movement `receive`, ref `route_return`)
- **คืนของเสีย (ชิ้น)** + อาการเสีย + ป้ายที่ถอดออก → **ไม่บวกสต็อก** สร้างใบของเสียรอคลังรับ
- **ของเสียนอกยอดเบิก** (ถอดจากป้ายแต่ไม่ได้เบิกไป) → สร้างใบของเสียเช่นกัน แต่ไม่หักยอดค้าง

ตรวจยอด: ของดี + ของเสีย ≤ ยอดที่ยังค้าง
บรรทัดปิดเมื่อ ติดตั้ง + คืนดี + คืนเสีย = จำนวนที่เบิก

แสดงในแท็บ "รอรับคืน" เป็นคอลัมน์: เบิก / ติดตั้ง / คืนดี / คืนเสีย / ค้าง

## 2. ของเสียต้องให้คลังกดรับเข้า (ใช้กลไกที่มีอยู่แล้ว)
ใบของเสียที่สร้างจะถูกบันทึกเป็น `defective_returns` สถานะ `pending_warehouse_entry`
→ ไปโผล่ที่ **รับคืนของเสีย > แท็บ "รอดำเนินการ"** ให้เจ้าหน้าที่คลังกด "ยืนยันรับเข้า" (หรือตีกลับให้แก้)
→ ตอนยืนยันเท่านั้นที่ระบบตัดของเข้าคลังของเสีย (WH-DEFECT) และลง stock movement
ข้อดี: ไม่สร้าง flow ใหม่ ใช้หน้าจอ/สิทธิ์/การตรวจสอบเดิมทั้งหมด

```text
รับคืนหน้างาน → [ของเสีย] รอคลังรับเข้า → คลังยืนยัน → เข้าคลังของเสีย → ประเมิน/เคลม/ทำลาย
                → [ของดี]  เข้าสต็อกทันที
```

## 3. MP / จอภาพ ที่ถอดจากป้าย → ต่อเข้าเมนู Swap
เมื่อรายการที่คืนเป็น MP หรือจอภาพ:
- ระบบ **ดึงป้ายที่ติดตั้งอยู่มาแสดงอัตโนมัติ** (จาก `media_players.billboard_id` / ประวัติการติดตั้ง) ไม่ต้องเลือกเอง แก้ได้ถ้าไม่ถูก
- **บังคับกรอกอาการเสีย** (เลือกจาก Master Data `mp_symptoms` + ช่องรายละเอียดเพิ่ม)
- เมื่อคลังยืนยันรับเข้าแล้ว ระบบสร้าง **คำขอ Swap อัตโนมัติ** ใน `swap_requests` สถานะ `pending`
  พร้อมข้อมูล: ป้าย, เครื่องเก่า + S/N, อาการเสีย, เอกสารต้นทาง

**ที่เมนู "Swap อุปกรณ์/MP" จะเห็นที่ไหน**
- แท็บ **"รายการคำขอ"** เพิ่มตัวกรองสถานะ **"รอ Swap"** (`pending`) — รายการที่มาจากของเสียจะขึ้นตรงนี้ พร้อม Badge "จากของเสีย"
- กดปุ่ม "เริ่ม Swap" ที่รายการนั้น → เด้งเข้าแท็บ "แจ้ง Swap ใหม่" โดย pre-fill ป้าย + เครื่องเก่า + อาการ ให้แล้ว เหลือแค่เลือกเครื่อง Spare
- แท็บ "แจ้ง Swap ใหม่" เพิ่มแถบแจ้งเตือนด้านบน "มี N รายการของเสียรอ Swap"

## 4. คำแนะนำว่าควรไปทางไหน
แนะนำ **สร้างคำขอ Swap ตอนคลังยืนยันรับเข้า** (ไม่ใช่ตอนหน้างานคืน) เพราะ
- ของยังไม่ถึงคลัง = ยังไม่ยืนยันว่าเสียจริง สร้างคำขอไว้ก่อนจะมีขยะค้างระบบ
- คลังคือคนรู้ว่าเครื่อง Spare มีพอหรือไม่
- ยอดสต็อกกับใบคำขอเกิดพร้อมกัน ตรวจสอบย้อนหลังง่าย

และแนะนำให้ **สร้าง Swap เฉพาะ MP/จอภาพ** เท่านั้น อะไหล่ทั่วไปไม่ต้อง (ปกติเบิกใหม่ ไม่ต้อง Swap ทีละเครื่อง)

## รายละเอียดเชิงเทคนิค
- Migration `goods_issue_pending_items`: เพิ่ม `returned_good_qty`, `returned_defective_qty` (numeric default 0), `returned_at`, `returned_by`, `return_location_id` — nullable/มี default ทั้งหมด ข้อมูลเก่าไม่พัง
- `goods_issue_pending.return_quantity` sync เป็นผลรวมทุกบรรทัด เพื่อไม่ให้รายงานเดิมเพี้ยน
- `defective_returns`: ใช้ `source_type = 'from_issue'`, เก็บ `symptom_id`/`reason`, `billboard_id`, และอ้างเอกสารเบิกต้นทาง
- สร้าง swap request ที่จุด "ยืนยันรับเข้า" ใน `DefectiveReturnEntry.tsx` เมื่อ `is_media_player = true` และมี `billboard_id`
- แก้ `IncompleteIssues.tsx` (Dialog + คอลัมน์ + filter), `DefectiveReturnEntry.tsx` (auto-create swap), `SwapWizard.tsx` (filter `pending` + prefill + banner)
- ไม่แตะ IssueGoods / DeliveryConfirmation / ManagerApproval
