# Audit Trail กลาง (ครอบทุกเมนูสำคัญ)

## ตอบคำถามก่อน: ตอนนี้ "ใครเบิกจ่าย" เก็บที่ไหน

ไม่มีตาราง log แยก — เก็บเป็นคอลัมน์ในใบเบิกเอง (ตาราง `goods_issue_pending`):

| ขั้นตอน | คอลัมน์ | บันทึกจากหน้า | ดูได้ที่หน้า |
|---|---|---|---|
| สร้างคำขอเบิก | `created_by` | ขอเบิกสินค้า | รายการเบิก (ไม่ได้แสดงชื่อ) |
| อนุมัติ / ไม่อนุมัติ | `approved_by`, `approved_at`, `approval_notes` | อนุมัติการเบิก | อนุมัติการเบิก (คอลัมน์ผู้อนุมัติ) |
| จ่ายของ | `issued_by`, `issued_at` | จ่ายสินค้า | ไม่ได้แสดงชื่อในหน้าใด |
| รับคืน | `returned_by` (ทั้งใบและรายชิ้น) | รายการเบิกที่ยังไม่สมบูรณ์ | ไม่ได้แสดงชื่อ |

ข้อจำกัด: เป็นค่าล่าสุดค่าเดียว ถ้ามีการแก้/ทำซ้ำ ค่าเดิมถูกทับและหายไป และไม่รู้ว่าตอนนั้นผู้ใช้ถือสิทธิ์อะไร

## สิ่งที่จะทำ

ตาราง audit กลาง 1 ตัว + trigger อัตโนมัติ + หน้ารายงานรวม + ไทม์ไลน์ในใบงาน

### ขอบเขตเมนูที่เก็บ log
เบิกจ่าย (คำขอ/อนุมัติ/จ่าย/รับคืน), รับเข้าสินค้า, Swap, ประเมิน MP, เคลม, ยืม-คืนอุปกรณ์/เครื่องมือ, จัดส่งตรง, ใบขอซื้อ (PR), และการเปลี่ยนสิทธิ์ผู้ใช้ (บทบาท/ฟังก์ชัน/ฝ่าย/แผนก)

ของเสียมี audit ของตัวเองอยู่แล้ว — จะดึงมารวมแสดงในรายงานกลางด้วย ไม่ย้ายข้อมูล

### สิ่งที่บันทึกทุกครั้ง
- โมดูล, เลขที่เอกสาร, ประเภทการกระทำ (สร้าง / แก้ไข / อนุมัติ / ปฏิเสธ / จ่าย / รับคืน / ยกเลิก / ลบ)
- ผู้ทำ (ชื่อ + อีเมล), **บทบาทที่ถืออยู่ ณ ขณะนั้น** (เช่น admin, warehouse_staff), ธง Super Admin
- ฝ่าย/แผนกของเอกสาร, สถานะก่อน → หลัง, ค่าที่เปลี่ยนแปลง, หมายเหตุ, เวลา

### หน้าใหม่
รายงาน → "ประวัติการใช้งานระบบ (Audit Trail)"
- ตัวกรอง: โมดูล, ผู้ใช้, ประเภทการกระทำ, ช่วงวันที่, ฝ่าย, เลขที่เอกสาร
- กรองเฉพาะ: การกระทำโดย Super Admin / การอนุมัติโดยคนเดียวกันหลายชั้น / การแก้ไขย้อนหลัง
- Export Excel, Pagination, ค้นหาข้อความ

### ในใบงานเดิม
เพิ่มแท็บ/ส่วน "ประวัติการดำเนินการ" (ไทม์ไลน์) ในหน้ารายละเอียดของ: อนุมัติการเบิก, จ่ายสินค้า, รับเข้าสินค้า, Swap, ประเมิน, เคลม — ใช้คอมโพเนนต์เดียวกันทั้งหมด

### สิทธิ์
- ฟังก์ชันใหม่ `activity_audit_view` — เห็นรายงานกลาง (แนะนำให้ Admin / บัญชี / ผู้ตรวจสอบ)
- ไทม์ไลน์ในใบงาน: ใครเข้าใบนั้นได้ก็เห็นได้ (ตามสิทธิ์ฝ่ายเดิม)
- ห้ามแก้/ลบ log ทุกกรณี (แม้ Super Admin) — เขียนได้เฉพาะระบบ

## รายละเอียดทางเทคนิค

- ตาราง `activity_audit`: `module`, `entity_table`, `entity_id`, `doc_number`, `action`, `actor_id`, `actor_name`, `actor_roles text[]`, `is_super_admin_action`, `department`, `status_before`, `status_after`, `changed_fields jsonb`, `notes`, `created_at` + index (`module`,`created_at`), (`entity_table`,`entity_id`), (`actor_id`)
- ฟังก์ชัน `log_activity()` แบบ generic (SECURITY DEFINER) อ่าน `auth.uid()` + `user_roles` แล้ว INSERT — ผูกเป็น AFTER INSERT/UPDATE trigger บนตารางในขอบเขต โดยระบุ mapping คอลัมน์สถานะ/เลขที่เอกสารต่อตาราง
- RLS: SELECT ให้ผู้ที่มี `activity_audit_view` หรือ admin/super_admin; ไม่มี policy INSERT/UPDATE/DELETE จากฝั่งแอป (เขียนผ่าน trigger เท่านั้น)
- คอมโพเนนต์ใหม่ `AuditTimeline` + `AuditTable` (reuse pattern จาก `DisposalAuditTimeline` / `DisposalAuditTable`)
- หน้าใหม่ `src/pages/AuditTrail.tsx` + route + เมนูใต้กลุ่ม "รายงาน" ใน `AppSidebar.tsx`
- ไม่ย้อนหลังข้อมูลเก่า — log เริ่มนับจากวันที่เปิดใช้ (ข้อมูลเดิมยังดูได้จากคอลัมน์ `*_by` เดิม)
