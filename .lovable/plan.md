# รับคืนแบบแยก "ของดี / ของเสีย" ต่อรายการ

## เคสตัวอย่างที่ต้องรองรับ
เบิก 10 ชิ้น (วัตถุประสงค์: ติดตั้งป้าย + ต้องคืน) ออก Route ซ่อม
- ใช้จริง 4 ชิ้น → ระบุป้าย 4 ชิ้น
- ไม่ได้ใช้ 6 ชิ้น → คืนของดีเข้าคลัง
- ถอดของเสียกลับมา 4 ชิ้น → เข้าสาย defective

ปัจจุบันระบบทำได้เฉพาะ "คืน" รวมทั้งใบ และคืนแล้วบวกเข้าสต็อกดีทั้งหมด จึงจับ 3 ก้อนนี้แยกกันไม่ได้

## สิ่งที่จะปรับ (ไม่กระทบ flow เดิม)

### 1. สรุปยอดต่อรายการ (ต่อบรรทัดสินค้า)
แต่ละบรรทัดในใบเบิกจะแสดงยอดครบวงจร:
```text
เบิก 10 = ติดตั้งแล้ว 4 + คืนของดี 6 + คืนของเสีย 0 + ค้าง 0
ของเสียถอดกลับ 4 ชิ้น (นับแยก ไม่หักจากยอดเบิก)
```
- "ติดตั้งแล้ว" = จำนวนที่ระบุป้ายไปแล้ว (ของเดิม)
- "คืนของดี" = บวกกลับเข้าสต็อกปกติ พร้อมเลือกฝ่าย/คลัง/ตำแหน่ง
- "ของเสียถอดกลับ" = ยิงเข้า `defective_returns` สถานะ `pending_warehouse_entry` ไปโผล่แท็บ "รอเข้าคลัง" ตามกลไกเดิม
- รายการจะปิด (`is_complete`) เมื่อ ติดตั้ง + คืนของดี + คืนของเสีย = จำนวนที่เบิก

### 2. Dialog รับคืนใหม่ (แทนของเดิมที่กรอกได้แค่ยอดเดียว)
เปิดจากปุ่ม "รับคืน" ที่ **ระดับบรรทัด** (เดิมอยู่ระดับใบ):
- ช่อง "คืนของดี (ชิ้น)" + ฝ่าย/คลัง/ตำแหน่งจัดเก็บ (ใช้ component เดิม)
- ช่อง "คืนของเสีย (ชิ้น)" + อาการเสีย/หมายเหตุ + ป้ายที่ถอดออกมา (ถ้ามี)
- ช่อง "ของเสียที่ถอดจากป้าย (นอกยอดเบิก)" สำหรับของที่ไม่ได้เบิกไป แต่ถอดกลับมา
- ตรวจสอบยอด: ของดี + ของเสีย ต้องไม่เกินยอดที่ยังค้าง
- ปุ่มเดียวบันทึกทั้งหมด (atomic ฝั่ง client — ทำของดีก่อน แล้วค่อยสร้าง defective)

### 3. ผลกระทบต่อสต็อก
- คืนของดี → `equipment.quantity_in_stock` +N, log `stock_movements` type `receive` (ref `route_return`)
- คืนของเสีย → **ไม่บวกเข้าสต็อกดี** สร้าง `defective_returns` รอเข้าคลัง (ตาม Defective Stock Control เดิม: ตัดเข้า WH-DEFECT)
- MP (สินค้ามี S/N) → คืนของดี set `quantity=1`, status `active`, เคลียร์ billboard; คืนของเสีย set `quantity=0`, status ตามสาย defective

### 4. แท็บ "รอรับคืน" ปรับการแสดงผล
- แสดงคอลัมน์: เบิก / ติดตั้ง / คืนดี / คืนเสีย / ค้าง (แทนคอลัมน์ คืนแล้ว อย่างเดียว)
- แถวขยายดูรายบรรทัดพร้อมปุ่มรับคืนของบรรทัดนั้น
- Badge เตือนสีส้มเมื่อยังมีค้าง, สีเขียวเมื่อครบ

## รายละเอียดเชิงเทคนิค
