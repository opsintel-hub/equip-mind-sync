
## เป้าหมาย
แยกบทบาทให้ชัด: **ช่าง = ขอเบิก + แจ้งคืน**, **คลัง = จ่าย + รับคืน** และปรับรายงานให้ครอบคลุมเครื่องมือทั้งหมด (ไม่ใช่แค่ผู้ถือครอง)

---

## 1. แยก Flow เบิก-คืน ให้ครบลูป (ไม่ซ้ำซ้อน)

Status lifecycle ใหม่ (เพิ่ม `pending_return` 1 ตัว):

```text
[ช่าง]                    [คลัง]
ขอเบิก ─► pending ─────► อนุมัติ ─► pending_issue ─► จ่าย ─► issued
                                                                 │
                                              [ช่าง]แจ้งคืน ◄────┘
                                                    │
                                                    ▼
                                              pending_return
                                                    │
                                              [คลัง]รับคืน
                                                    │
                                                    ▼
                                                returned
```

## 2. ปรับ 4 เมนู + เพิ่มใหม่ 1 เมนู

| เมนู | ใคร | เห็นอะไร | ปุ่ม |
|---|---|---|---|
| **ขอเบิกเครื่องมือ** | ช่าง (เจ้าของคำขอ) | คำขอของตัวเอง | สร้างใหม่, ยกเลิก (เฉพาะ `pending`/`pending_issue`) — **ตัดปุ่มจ่าย/อนุมัติออก** |
| **คลังจ่ายเครื่องมือ** | คลัง/Admin | คิว `pending` + `pending_issue` ทุกฝ่ายที่ดูได้ | อนุมัติ, จ่าย, ยกเลิก |
| **ขอคืนเครื่องมือ** *(ช่าง)* | ช่าง | เครื่องมือที่ตัวเองถืออยู่ (`issued`) | **แจ้งคืน** (ส่งเข้า `pending_return` พร้อมกรอกสภาพ/หมายเหตุ) — ไม่มีปุ่มรับคืน |
| **คลังรับคืนเครื่องมือ** *(ใหม่)* `/tool-loans/receive-return` | คลัง/Admin | คิว `pending_return` | รับคืน (คืนสต็อก + set `returned`), ปฏิเสธ (กลับ `issued`) |
| **รายงานเครื่องมือ** *(เปลี่ยนชื่อจาก "รายงานผู้ถือครอง")* | ทุกคน | ดูตามสิทธิ์ฝ่าย | ดูอย่างเดียว |

## 3. รายงานเครื่องมือ (`/tool-loans/report`)

เปลี่ยนชื่อเมนู + เพิ่ม **Tab "เครื่องมือทั้งหมด"** เป็น Tab แรก:

- **Tab 1: เครื่องมือทั้งหมด** *(ใหม่)* — 1 บรรทัด/1 เครื่องมือ
  - คอลัมน์: รหัส, ชื่อ, ฝ่ายเจ้าของ, จำนวนคงเหลือคลัง, จำนวนถูกเบิกไป, ผู้ถือครอง (ถ้ามี), สถานะประกัน
  - ตัวกรอง: **สถานะที่อยู่** (ทั้งหมด / อยู่คลัง / ถูกเบิกไปแล้ว), **ฝ่าย**, **หมวด/หมวดย่อย**, **ประกัน** (ปกติ/≤30วัน/หมด), **ประเภท** (ทรัพย์สิน/ประจำตัวช่าง), ค้นหา รหัส/ชื่อ/S/N
- **Tab 2: ตามผู้ถือครอง** *(เดิม)*
- **Tab 3: ตามเครื่องมือ** *(เดิม)*

## 4. บังคับกำหนดคืน + Highlight เกินกำหนด

- ฟอร์มขอเบิก: `due_date` เป็น **required** (ยกเว้นเครื่องมือ `return_required=false` เช่นวัสดุสิ้นเปลือง — ซ่อน field)
- ทุกตารางที่แสดง loans: **จัดเรียง overdue ขึ้นบนสุด** + row สีแดงอ่อน (`bg-destructive/5`) + Badge "เกินกำหนด X วัน"

## รายละเอียดทางเทคนิค

- **Migration:** เพิ่ม status `pending_return` ใน `STATUS_META` (ไม่ต้องแก้ schema เพราะ status เป็น text)
- **ToolLoans.tsx:** 
  - เพิ่ม mode `receive-return`
  - ปุ่ม "แจ้งคืน" (mode=`return`): update status → `pending_return` พร้อมเก็บ `return_notes` (สภาพ+หมายเหตุ) แต่ยังไม่คืนสต็อก ยังไม่ set `return_date`
  - ปุ่ม "รับคืน" (mode=`receive-return`): เดิมของ `handleReturn` — คืนสต็อก + `returned` + `return_date`
  - `modeFilter`: `return` → `status === 'issued'`; `receive-return` → `status === 'pending_return'`
  - บังคับ `due_date` required + validation
  - Sort overdue-first ใน `renderTable`
- **ToolLoansReport.tsx:** เพิ่ม Tab `all` เป็น default พร้อม query `tools` + join loans ปัจจุบัน
- **App.tsx:** เพิ่ม route `/tool-loans/receive-return`
- **AppSidebar.tsx:** เพิ่มเมนู "คลังรับคืนเครื่องมือ" + rename "รายงานผู้ถือครอง" → "รายงานเครื่องมือ"

## ประหยัดเครดิต
- ใช้ component `ToolLoans.tsx` เดิมทุก mode (ไม่สร้างไฟล์ใหม่สำหรับ receive-return)
- ไม่ต้อง migration
- Tab ใหม่ในรายงานใช้ query เดียวกับที่มีอยู่แล้ว
