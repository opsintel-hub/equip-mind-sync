# แก้ปัญหา Prefix และรหัสอุปกรณ์ / เครื่องมือ / Media Player

## สิ่งที่ตรวจพบ

- ปุ่มลบ Prefix ตอนนี้ไม่ได้ลบจริง แต่แค่ "ปิดการใช้งาน" และถ้าบันทึกไม่ผ่านสิทธิ์ ระบบขึ้นข้อความกลาง ๆ ว่า "ไม่สามารถลบ Prefix ได้" โดยไม่บอกสาเหตุ
- รูปแบบรหัสไม่ตรงกัน: ระบบสร้างรหัสจากหน้าจอเป็นแบบ **เว้นวรรค** เช่น `BUS 0006` แต่ข้อมูลอุปกรณ์ที่นำเข้ามาแล้ว 27 รายการเป็น `PBUS0001`–`PBUS0027` (ไม่เว้นวรรค)
- Prefix `PBUS` ไม่มีอยู่ในทะเบียน Prefix เลย (ในทะเบียนมี 711, AIR, BUS, DGT, INK, OSM, STT, TEST) ระบบจึงไม่รู้ว่าเลขรันถึงไหนแล้ว → นำเข้าครั้งต่อไปหรือสร้างรหัสใหม่มีโอกาสชนกัน

## สิ่งที่จะทำ

### 1. ปุ่มลบ Prefix ใช้งานได้จริง + บอกสาเหตุชัดเจน
ทำเหมือนกันทั้ง 3 ที่ (อุปกรณ์ / เครื่องมือ / Media Player):
- ก่อนลบ ระบบจะนับว่ามีสินค้าที่ใช้ Prefix นี้อยู่กี่รายการ
  - ถ้า **ไม่มีการใช้งาน** → ลบออกจากรายการจริง
  - ถ้า **มีการใช้งานอยู่** → หน้าต่างยืนยันจะบอกว่า "มี N รายการใช้ Prefix นี้ เช่น BUS 0001, BUS 0002 …" แล้วให้เลือก "ปิดการใช้งาน" แทน (รหัสเดิมไม่กระทบ แต่จะไม่ถูกเลือกไปสร้างรหัสใหม่อีก)
- ถ้าบันทึกไม่สำเร็จ จะแสดงสาเหตุจริงจากระบบ เช่น สิทธิ์ไม่พอ แทนข้อความกลาง ๆ
- เปิดสิทธิ์จัดการ Prefix เครื่องมือให้ Super Admin ด้วย (ตอนนี้กติกาฝั่งฐานข้อมูลยังไม่ครอบคลุม จึงกดลบไม่ผ่าน)

### 2. รูปแบบรหัสมาตรฐานเดียว = `PREFIX 0000` (เว้นวรรค)
- ยืนยันรูปแบบนี้กับทั้ง 3 ประเภท และแสดงตัวอย่างรหัสถัดไปกำกับในหน้าจัดการ Prefix
- รหัสเดิมที่ไม่เว้นวรรค (PBUS0001–PBUS0027) **ไม่ถูกแก้** ยังใช้งานและค้นหาได้ตามปกติ

### 3. นำเข้าไฟล์แล้วรหัสไม่หลุดจากระบบอีก
- ตอนตรวจไฟล์ก่อนนำเข้า ระบบจะแยกรหัสเป็น "ส่วน Prefix + เลขรัน" และแสดงสรุปให้เห็นก่อนกดนำเข้า เช่น
  - `PBUS` — ยังไม่มีในทะเบียน จะสร้างให้อัตโนมัติ (12 แถว)
  - `BUS` — มีอยู่แล้ว เลขรันจะขยับจาก 0006 เป็น 0021
- ถ้ารหัสในไฟล์มีปัญหา จะ **บล็อกและฟ้องรายแถว**: บอกเลขแถวในไฟล์ รหัสที่ผิด สาเหตุ (เช่น รหัสซ้ำในไฟล์, ซ้ำกับในระบบ, รูปแบบไม่ถูกต้อง, เลขรันซ้ำกับรหัสเดิม) และวิธีแก้ที่ควรทำก่อนนำเข้าใหม่ พร้อมปุ่มคัดลอกรายการปัญหา
- เมื่อนำเข้าสำเร็จ ระบบจะ **สร้าง Prefix ที่ยังไม่มีให้อัตโนมัติ และอัปเดตเลขรันถัดไป** ให้สูงกว่าเลขสูงสุดที่นำเข้าเสมอ

### 4. ซ่อมเลขรันของข้อมูลที่นำเข้าไปแล้ว
รันปรับครั้งเดียว: ลงทะเบียน Prefix `PBUS` และตั้งเลขรันถัดไปเป็น 0028 เพื่อไม่ให้รหัสใหม่ชนของเดิม พร้อมตรวจ Prefix อื่น ๆ ให้เลขรันสูงกว่ารหัสที่มีจริงทั้งหมด
