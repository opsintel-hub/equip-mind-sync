# แยกการมองเห็นข้อมูลระดับ "แผนก" (Section) เพิ่มจากระดับ "ฝ่าย" (Department)

## เป้าหมาย
ปัจจุบันผู้ใช้เห็นของเฉพาะฝ่ายที่มีสิทธิ์ ต้องการลงลึกอีกชั้น: ภายในฝ่ายเดียวกัน แต่ละแผนกเห็นของคนละชุด
เช่น ฝ่าย Airport → แผนกช่างเห็นเฉพาะอะไหล่, แผนก PM เห็นเฉพาะ Media Player และอุปกรณ์ที่เกี่ยวกับ MP

## ข้อสรุปจากที่ตกลงกัน
- แบ่งของด้วย **หมวดหมู่** (ไม่ต้องไล่ติดแท็กรายชิ้น)
- ผู้ใช้ที่ไม่มีสิทธิ์แผนกนั้น **ไม่เห็นรายการเลย**
- ผู้ใช้ 1 คน สังกัดได้ **หลายแผนก** และหลายฝ่าย
- ปรับ **ทั้งระบบ** ทุกหน้าที่มีรายการสินค้า / MP / เครื่องมือ
- Super Admin เห็นทุกอย่างเหมือนเดิม

## หลักการทำงาน
```text
ผู้ใช้ ── มีสิทธิ์ฝ่าย (เดิม) ──▶ กรองด้วยคอลัมน์ department
      └─ มีสิทธิ์แผนก (ใหม่) ──▶ แผนกผูกกับ "ขอบเขตหมวดหมู่"
                                    ├─ หมวดหมู่อุปกรณ์ (categories / subcategories)
                                    ├─ หมวดหมู่เครื่องมือ (tool_categories / subcategories)
                                    └─ ประเภท Media Player (device_type เช่น MP, จอภาพ)
รายการที่แสดง = อยู่ในฝ่ายที่เห็นได้ AND อยู่ในหมวดหมู่ที่แผนกของตนครอบคลุม
```
ถ้าผู้ใช้ยังไม่ถูกกำหนดแผนกใดเลย → ใช้พฤติกรรมเดิม (เห็นทุกหมวดในฝ่ายที่มีสิทธิ์) เพื่อไม่ให้ผู้ใช้เดิมพังทันทีหลังอัปเดต

## งานที่ต้องทำ

### 1. ฐานข้อมูล
- ตาราง `section_scopes` — ผูกแผนก (`sections.id`) กับขอบเขต: `scope_type` (`equipment_category`, `equipment_subcategory`, `tool_category`, `tool_subcategory`, `mp_device_type`) + ค่าอ้างอิง
- ตาราง `user_sections` — ผู้ใช้ ↔ แผนก (หลายแถวได้) พร้อม `can_view/can_create/can_edit/can_delete`
- ฟังก์ชัน security definer `get_user_section_scopes(_user_id)` คืนรายการหมวดที่ผู้ใช้เห็นได้ และ `user_has_section(_user_id, _section_id)`
- RLS + GRANT ครบตามมาตรฐานโปรเจ็กต์ (admin/super_admin จัดการได้, ผู้ใช้อ่านของตัวเองได้)

### 2. หน้าจัดการสิทธิ์ (Admin)
- `PermissionWizard` / `UserPermissionManager`: เพิ่มขั้นตอนเลือก "แผนก" (checkbox หลายแผนก) ที่กรองตามฝ่ายที่เลือกไว้ในขั้นก่อนหน้า
- `PermissionMatrix` แสดงคอลัมน์แผนกเพิ่ม
- Master Data → แผนก: เพิ่มแท็บ/ไดอะล็อก "ขอบเขตหมวดหมู่ของแผนก" เพื่อเลือกหมวดอุปกรณ์ / หมวดเครื่องมือ / ประเภท MP ที่แผนกนั้นดูแล

### 3. Hook กลาง
- `useSectionScope()` คู่กับ `useDeptScope()` ที่มีอยู่ คืน `isSuperAdmin`, `sectionIds`, `allowedEquipmentCategories`, `allowedSubcategoryIds`, `allowedToolCategoryIds`, `allowedDeviceTypes`, `scopeKey` และ helper
  - `applyEquipmentScope(query)` → `.in("category", ...)` / `.in("subcategory_id", ...)`
  - `applyToolScope(query)`, `applyMediaPlayerScope(query)`
  - `filterItemsByScope(rows)` สำหรับข้อมูลที่ดึงมาแล้ว
- ถ้าไม่มีข้อมูลแผนก → ไม่กรอง (คงพฤติกรรมเดิม)

### 4. ปรับหน้าจอทั้งระบบ (ต่อยอดจากการกรองฝ่ายที่ทำไว้แล้ว)
เพิ่ม section scope ใน: นำสินค้าเข้าระบบ/Delivery Entry, รับสินค้าเข้าคลัง, ขอเบิกสินค้า, จ่ายสินค้า, อนุมัติเบิก, รายงานสต๊อก/Stock Card, รายงานคลัง, Media Player (รายการ/รายงาน/Swap/ประเมิน/เคลม), เครื่องมือ (รายการ/ยืม/PM), คืนของเสีย, Dashboard/KPI และช่องค้นหา `SearchableSelect` ที่ค้นฝั่งเซิร์ฟเวอร์
รวมถึงเพิ่มตัวกรอง "แผนก" ในหน้าที่มีตัวกรองฝ่ายอยู่แล้ว (ล็อกตามสิทธิ์ เหมือน `DepartmentMultiFilter`)

### 5. ตรวจสอบ
- ทดสอบด้วยผู้ใช้ตัวอย่าง 3 แบบ: Super Admin, ผู้ใช้แผนกช่าง, ผู้ใช้แผนก PM — ยืนยันว่ารายการที่เห็นตรงตามขอบเขต และหน้าที่ไม่มีสิทธิ์ไม่มีข้อมูลรั่ว

## หมายเหตุทางเทคนิค
- `equipment.category` เก็บเป็นข้อความ ส่วน `subcategory_id` เป็น uuid — `section_scopes` จึงเก็บทั้ง `ref_id (uuid)` และ `ref_text` เพื่อรองรับทั้งสองแบบ
- `media_players` ไม่มีหมวดหมู่ ใช้ `device_type` เป็นเกณฑ์
- ปัจจุบันตาราง `sections` มีข้อมูลเพียง 2 แถว (Digital Media → QC, คลังแสงMA) ต้องเพิ่มแผนกจริงของแต่ละฝ่ายก่อนใช้งานจริง
- การกรองเป็นระดับ UI/Query เป็นหลัก; RLS ระดับฝ่ายเดิมยังคงอยู่ ไม่แตะ policy ของตารางสินค้าเพื่อลดความเสี่ยงข้อมูลหาย
