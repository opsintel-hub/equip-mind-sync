# Project Architecture Rules

- Clear the cross-tab session mirror only after an explicit user sign-out; an unauthenticated tab must never invalidate another tab's active session, preventing login/logout races.- Special requests: types live in a frontend registry (requestTypes.ts) with free-text request_type; only auto types need logic in review_special_request RPC — adding types needs no schema change.
- Special requests UI is split by role: /my-special-requests (requester, own rows) and /special-requests (Super Admin only) share one page component via a mode prop; RLS remains the real boundary.
- Outstanding issued inventory uses shared issueQuantities helpers and a read-only, department-scoped tab independent of purpose flags; this keeps report/export totals consistent without changing stock workflows.
- Inter-warehouse transfer reuses issue documents with immutable warehouse_transfer_batches and atomic authenticated dispatch/receipt RPCs: dispatch removes available stock into transit, receipt restores it at the destination, and transferred_qty excludes transfer lines from return/install queues; historical immediate transfers remain untouched.
- Receipt storage defaults use a pure permission-aware helper so inaccessible or inactive legacy locations cannot be selected automatically.
- Magic Ticket Integration runs as one edge function (`magic-ticket`) whose writes (work-log, revert, bind-ticket, issue-request) go through SECURITY DEFINER RPCs executable only by service_role; API keys are stored hashed with optional per-key IP allowlists so Super Admin manages access without secrets. Reverting an event clears its serial_number (kept in reverted_serial_number) so existing availability checks need no change.
- Guard checkpoint has a no-email Station PIN mode: `/gate/:code` calls the `gate-station` edge function (service role) with a short-lived station token; PINs are bcrypt-hashed and verified only via service_role RPC, so guards never get app accounts.
- Issue return form selection and quantity balancing use shared pure helpers so document-scoped billboard choices and quantity boundaries can be tested without stock writes.
- Issue returns use an authenticated atomic RPC for capacity validation, per-billboard defective tickets and uninstall histories; installation notes tag the issue-item ID to disambiguate repeated equipment lines while legacy document notes remain supported.
- Sensitive contact and permission tables restrict SELECT to approved users (public.is_approved_user = has any user_roles row), owners, or admins; avoids breaking joins while blocking unapproved sign-ups.
- Lost/stolen replacement close-out uses the record_lost_replacement RPC: it adds to both lost_replacement_qty (reporting, with a jsonb log of who/when/why/photos) and written_off_qty, so all existing balance math keeps working without changes; capped by installed and outstanding qty, equipment only, no approver. Both UI and RPC allow this only when the purpose requires billboard AND return, because other purposes already close installed quantities and their outstanding balance is unused stock.
- Site access tickets: placement-location assignment is retired; exit photos are optional; forgotten tickets are closed only via admin_close_access_ticket RPC (department Admin or Super Admin) which stamps admin_closed_* for audit; booking lead-time tiers are computed client-side from created_at vs planned_start_at in siteAccess.ts so no schema change is needed to adjust thresholds.
- Site-access analytics use a read-only approved-user, department-scoped RPC with minimal non-contact fields; shared pure Bangkok-time event helpers separately aggregate creation, planned visits and actual entries, and exclude admin close-outs from dwell times to avoid misleading staffing statistics.
